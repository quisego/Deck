# Getting started

Follow these steps in order. Each step has a simple check, so you know it works before you go on.

## 1. What you need

**Hardware:** the parts from [hardware.md](hardware.md), an ST-LINK programmer, a USB cable for the ESP32,
and (optional) a USB-UART adapter for the STM32 debug log.

**Software:**

| Tool | Used for |
|---|---|
| ARM GNU toolchain (`arm-none-eabi-gcc`), CMake 3.22+, Ninja | Build the STM32 firmware |
| STM32CubeProgrammer or the VS Code STM32 extension | Flash the STM32 |
| ESP-IDF 5.x (5.1 or newer, because the code uses `esp_netif_sntp`) | Build and flash the ESP32 |
| An MQTT broker, for example Mosquitto | Message exchange |
| Python 3.10+ on Windows 10/11 | `deckd` and `deckctl` |

## 2. Wire the hardware

Use the table in [hardware.md](hardware.md). Remember the **common ground** between the STM32 and the ESP32,
and the cross connection of the UART wires (TX -> RX).

## 3. Build and flash the STM32

The project is generated by STM32CubeMX and uses CMake.

```bash
cd stm32
cmake --preset Debug            # if your project has CMake presets from CubeMX
cmake --build --preset Debug
```

If you do not have presets, open the `stm32` folder in VS Code with the STM32 extension (or configure CMake with your
`arm-none-eabi` toolchain file), build the target `stm32`, and flash the `.elf` file with ST-LINK.

The `common/proto` library is added by `stm32/CMakeLists.txt` automatically.

**Check:** connect a USB-UART adapter to PA2 (USART2 TX), open a terminal at 115200 baud. After reset you should see:

```
... I ...: Logger is initialized.
... I ...: Link module initialized.
... I ...: Supervisor is initialized.
... I ...: SSD1306 initialized.
... I ...: DS1307 initialized.
... I ...: BME280 initialized.
```

The OLED shows date, time, temperature, humidity and pressure.

## 4. Start an MQTT broker

Example with Mosquitto (a local test setup without a password):

```
# mosquitto.conf
listener 1883
allow_anonymous true
```

```bash
mosquitto -c mosquitto.conf -v
```

Write down the IP address of this computer. The ESP32 needs it.

## 5. Configure, build and flash the ESP32

```bash
cd esp32
idf.py set-target esp32s3
idf.py menuconfig
```

Open **App Configuration** and set:

| Option | Meaning | Example |
|---|---|---|
| `APP_WIFI_SSID`, `APP_WIFI_PASSWORD` | Your Wi-Fi | - |
| `APP_MQTT_URI` | Broker address | `mqtt://192.168.0.10:1883` |
| `APP_MQTT_USER`, `APP_MQTT_PASSWORD` | Leave empty for no authorization | - |
| `APP_MQTT_BASE_TOPIC` | Topic prefix (the PC config must use the same) | `stm32bridge` |
| `APP_MQTT_RTC_PERIOD_S` | How often the time is published | `10` |
| `APP_STM_TIMEOUT_S` | Seconds of silence before the STM32 is "offline" | `30` |
| `APP_TZ` | Time zone (POSIX format) | `EET-2EEST,M3.5.0/3,M10.5.0/4` |
| `APP_RTC_SYNC_ON_SNTP` | Write the internet time to the DS1307 | on |

> Do not commit your real Wi-Fi password to Git.

Build and flash:

```bash
idf.py build flash monitor
```

**Check:** in the monitor you should see `Link module initialized successfully`, then Wi-Fi and MQTT connection
messages, then lines such as `ENV: T=23.45 C, RH=45.67 %, P=1013.25 hPa` and `STM32: up ... s`.

Check MQTT from any computer:

```bash
mosquitto_sub -h <broker-ip> -t "stm32bridge/#" -v
```

You should see `stm32bridge/status online`, sensor values, and button events when you press a button.

## 6. Set the time (optional)

If SNTP is on, the time is set automatically. You can also set it by hand:

```bash
mosquitto_pub -h <broker-ip> -t "stm32bridge/cmd/rtc/set" -m "2026-11-12 12:00:00"
```

The answer comes on `stm32bridge/cmd/rtc/result` (`ok` or `error`).

## 7. Run the PC daemon

```bash
cd pc
pip install -r requirements.txt
python deckd.py
```

`deckd` must run in your normal user session (not as a Windows service).

The config file is `%APPDATA%\deck\config.yaml` (or the path from the `DECK_CONFIG` variable).
If it does not exist, defaults are used: broker `127.0.0.1:1883`, base topic `stm32bridge`, IPC port `47800`.
Set your broker address there if it runs on another computer.

Example `config.yaml`:

```yaml
base_topic: stm32bridge
mqtt:
  host: 192.168.0.10
  port: 1883
```

## 8. Create bindings with `deckctl`

```bash
python deckctl.py status                       # active application and MQTT state
python deckctl.py windows                      # applications with visible windows
python deckctl.py bind add --exe Code.exe --keys ctrl+shift+t
# -> "Press a button on the deck..."  (press the button within 15 s)
python deckctl.py bind list
python deckctl.py bind remove --exe Code.exe --button 0x10
```

`--on` selects the event: `press` (default), `release`, `click` or `long` (long press).

**Check:** open the application, press the button. The hotkey must work in that application.

## 9. Troubleshooting

| Problem | What to check |
|---|---|
| OLED is empty | I2C wires, address `0x3C`, log line `SSD1306 init failed` |
| Time shows `--:--:--` | DS1307 wires and 5 V power, battery in the holder |
| No sensor values | SPI wires, CS on PA4, log line `BME280 init failed`; status flag `bme` in `stm/state` |
| No messages on the ESP32 | UART TX/RX are crossed, common ground, baud rate 115200 on both sides |
| `rx_crc_errors` grows | Long or noisy wires, wrong baud rate |
| MQTT does not connect | Broker IP, firewall (port 1883), user and password |
| `deckd` does not see button events | Same base topic on ESP32 and PC, broker address in `config.yaml` |
| Device resets every few seconds | Watchdog reset. The log shows `reset reason - IWDG` and the silent task name. |
